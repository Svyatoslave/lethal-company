# OPERATION: LAST NIGHT — NIGHT RAID

> Компания ценит вашу жизнь. Но не выше стоимости металлолома.

Система управления ночным рейдом для мальчишника: терминал оператора, мобильная панель ведущего и устройства экипажа. Один сервер, одна база SQLite, синхронизация в реальном времени через Socket.IO.

## Запуск

Нужен Node.js 22.13+ (используется встроенный `node:sqlite`, без нативных сборок).

```bash
npm install
npm run build
npm start
```

В консоли сервер выведет адреса (`https://192.168.x.x:8443`) и **PIN-коды** ведущего и оператора. PIN-коды хранятся в `data/secrets.json`. Их можно задать через переменные окружения `ADMIN_PIN` и `OPERATOR_PIN`.

Все устройства подключаются к одной Wi-Fi сети и открывают адрес по IP. Сертификат самоподписанный: при первом открытии браузер покажет предупреждение, нужно нажать «Дополнительно → Перейти». HTTPS нужен, чтобы на телефонах работала камера. Порт 8080 перенаправляет на HTTPS.

| Экран | Адрес | Кто |
|---|---|---|
| OPERATOR TERMINAL | `/operator` | ноутбук на базе |
| FIELD ADMIN | `/admin` | телефон ведущего |
| CREW DEVICE | `/crew` | телефоны игроков и монстров |
| Печать QR | `/print` | ведущий (нужен вход в FIELD ADMIN) |

Если вы стоите за прокси с настоящим TLS (cloudflared, Caddy), запускайте `npx tsx server/index.ts --http --port=8080`.

## Подготовка к игре

1. **FIELD ADMIN → MISSION**: создать миссию (квота, стартовый баланс, длительность вылазки, урон за опоздание и урон монстров в % здоровья).
2. **CREW**: добавить игроков (роль CREW) и двух монстров (роль MONSTER). У каждого появится личный код входа.
3. **SCRAP**: завести предметы заранее, пока миссия в режиме STANDBY. Можно вставить список, по одной строке на предмет: `Название; ценность; описание`. Можно добавить предметы по одному или сгенерировать случайные. Описание игрок увидит на телефоне после сканирования, а оператор — в SCRAP RECOVERY.
4. **Печать QR**: открыть `/print` **по IP-адресу сервера**, а не через localhost, иначе телефоны не откроют ссылки. Метки можно распечатать сразу, скачать по одной в PNG или все одним ZIP-архивом. В архив входит `items.csv` со ссылками. Если позже создаётся новая миссия, включите «Перенести предметы»: распечатанные QR продолжат работать.
5. Игроки сканируют свой бейдж обычной камерой телефона и попадают в CREW DEVICE.
6. **MISSION → ЗАПУСТИТЬ МИССИЮ**.

## Игровой цикл

1. Оператор отмечает до 4 сотрудников в CREW STATUS → «СФОРМИРОВАТЬ ГРУППУ».
2. OPEN GATE: сервер фиксирует время выхода и дедлайн каждого.
3. Найденные предметы игроки сканируют («◎ СКАНИРОВАТЬ ЛУТ» или камерой телефона) **между вылазками**: пока группа в поле, сканирование заблокировано у всех. Скан только фиксирует находку, кредиты не начисляются.
4. Монстры действуют сами. Коснувшись сотрудника, монстр отмечает удар на своём телефоне: «УДАР» по нужному игроку (только тем, кто за шлюзом). Со своего телефона монстр может писать только ведущему: это личный чат, оператор его не видит. Ведущий во вкладке THREAT добавляет атмосферу (движение, появление, эффекты, ложные тревоги) и переписывается с монстрами.
5. Оператор вручную жмёт «ВЕРНУЛСЯ» и «EXTRACT», когда человек и предмет физически на базе. Кредиты начисляются только после этого.
6. Кто не успел к дедлайну, получает статус OVERDUE и теряет здоровье (один раз за вылазку). В следующих вылазках такой игрок участвует как обычно.
7. На кредиты покупаются RADIO, BODY CAM, MEDKIT, TIME EXTENSION, THREAT SCANNER и EMERGENCY EXTRACTION. Сканер и эвакуацию исполняет ведущий: запрос появляется во вкладке THREAT.

## Здоровье (HP)

- У каждого сотрудника экипажа здоровье от 0 до 100%. Оно видно в колонке HP у оператора, у ведущего и крупно на телефоне игрока.
- **Опоздание** отнимает 50% (настраивается: FIELD ADMIN → AIRLOCK или MISSION).
- **Удар монстра** отнимает 50% (THREAT → «УРОН МОНСТРОВ»). Повторный удар по той же цели засчитывается не раньше чем через 10 секунд, чтобы двойное нажатие не сняло лишнее.
- **Само здоровье не восстанавливается.** Лечит только **MEDKIT**: оператор покупает её в магазине и выбирает раненого, одна аптечка даёт +25%. Ещё ведущий может выставить здоровье вручную.
- При 0% сотрудник **выведен из строя**: всем приходит тревога, на его телефоне появляется красная карточка. Пока его не вылечат, он **не может выходить за шлюз** (его нельзя выбрать в группу, а при открытии шлюза он остаётся на борту), **не может сканировать лут**, и монстр не может ударить его ещё раз. Если он упал за шлюзом, он возвращается на базу шагом, и оператор подтверждает возвращение как обычно. Вернуть его в строй может только аптечка (или ведущий вручную).
- **Ярость монстров** для финала: THREAT → «ЯРОСТЬ 100%». Один удар забирает всё здоровье. Любое изменение урона сразу объявляется тревогой на всех устройствах.

## Задания «оператор — сотрудник»

1. В FIELD ADMIN → **ЗАДАНИЯ** создайте терминал: название, инструкцию сотруднику, справочник оператору, правильный ответ и награду. «ЗАПОЛНИТЬ ПРИМЕР» подставляет готовую задачу с цветом индикатора и кодами.
2. Скачайте **QR · PNG** и разместите метку на площадке. Админку нужно открывать по адресу, доступному с телефонов, а не через localhost: этот адрес попадёт в QR. Метки терминалов содержат случайный токен, без ответа и награды.
3. Во время активной миссии сотрудник сканирует метку кнопкой **СКАНИРОВАТЬ QR** или обычной камерой телефона. Ссылка `/t/<token>` открывает CREW DEVICE; если нужен вход, терминал запоминается до ввода личного кода.
4. Терминал закрепляется за сотрудником. В **TERMINAL LINK** на его телефоне появляется инструкция, а у оператора — отдельный справочник. Сотрудник сообщает наблюдение по связи, оператор помогает определить код. Части задания разделены на сервере: сотрудник не получает справочник, оператор не получает инструкцию сотрудника; поле правильного ответа и QR-токен доступны только ведущему.
5. Сотрудник вводит код на телефоне. Сервер не учитывает регистр, крайние и повторяющиеся пробелы. После неверного ответа новая попытка доступна через три секунды. На паузе активация и ответы заблокированы.
6. Правильный ответ завершает задание и один раз начисляет награду в общий баланс. Прогресс квоты металлолома не меняется. Повторная отправка ответа не выдаёт награду снова.

Один терминал — одно общее выполнение за миссию. Пока он занят, другие сотрудники не могут его забрать. Ведущий может **ОСВОБОДИТЬ** незавершённый терминал, чтобы другой сотрудник отсканировал его заново. Изменение и удаление доступны только для свободного терминала; при изменении QR сохраняется. Завершённый терминал не сбрасывается. Задания не переносятся в следующую миссию, старые QR в ней недействительны.

Проверка игровой логики и разделения данных заданий: `npm run test:tasks`. Тест использует отдельную временную базу и не меняет данные игры.

## BODY CAM (камеры сотрудников)

- Камеры покупаются в магазине (BODY CAM, по умолчанию 300 CR) или выдаются ведущим: COMMS → «ВЫДАТЬ BODY CAM».
- Игрок сам включает камеру на телефоне кнопкой «ВКЛЮЧИТЬ BODY CAM». Пока его смотрят, он видит «В ЭФИРЕ · СМОТРЯТ N».
- Оператор нажимает **BODY CAMS** в верхней панели или **◉ CAM** у сотрудника. Каналы переключаются кликом, цифрами 1–9 или стрелками. «ВСЕ КАМЕРЫ» показывает сетку без звука.
- Связь односторонняя: оператор видит и слышит игрока, игрок оператора не слышит. Звук идёт только с выбранного канала.
- Видео идёт напрямую с телефона на экран оператора (WebRTC), сервер только помогает установить соединение. Внутри одной Wi-Fi сети этого достаточно. Для работы через интернет и мобильную связь нужен TURN-сервер (см. ниже).
- Камера работает, пока страница открыта и экран телефона не погашен. Глушение эфира ведущим отключает и камеры.

### Камеры через интернет: TURN (coturn)

TURN — это ретранслятор видео на случай, когда телефон и оператор не могут соединиться напрямую (мобильный интернет, разные сети). Ставится на тот же сервер, где работает игра. Пример для Ubuntu/Debian:

```bash
sudo apt install -y coturn
openssl rand -hex 32   # это будет TURN_SECRET
```

`/etc/turnserver.conf`:

```
listening-port=3478
tls-listening-port=5349
fingerprint
use-auth-secret
static-auth-secret=ВАШ_TURN_SECRET
realm=raid.example.ru
external-ip=ПУБЛИЧНЫЙ_IP_СЕРВЕРА
min-port=49160
max-port=49200
no-cli
no-multicast-peers
denied-peer-ip=10.0.0.0-10.255.255.255
denied-peer-ip=172.16.0.0-172.31.255.255
denied-peer-ip=192.168.0.0-192.168.255.255
# для turns: (TLS на 5349) укажите сертификат домена, например от Let's Encrypt:
# cert=/etc/letsencrypt/live/raid.example.ru/fullchain.pem
# pkey=/etc/letsencrypt/live/raid.example.ru/privkey.pem
```

```bash
sudo sed -i 's/^#\?TURNSERVER_ENABLED=.*/TURNSERVER_ENABLED=1/' /etc/default/coturn
sudo systemctl enable --now coturn
sudo ufw allow 3478 && sudo ufw allow 5349/tcp && sudo ufw allow 49160:49200/udp
```

Если у провайдера есть свой файрвол (Security Group), откройте те же порты и там.

Затем в папке игры создайте `.env` (образец — `.env.example`) и перезапустите игру:

```
TURN_URLS=turn:raid.example.ru:3478?transport=udp,turn:raid.example.ru:3478?transport=tcp,turns:raid.example.ru:5349?transport=tcp
TURN_SECRET=ВАШ_TURN_SECRET
```

При запуске сервер напишет `BODY CAM RELAY : TURN …`. Пароли к TURN выдаются устройствам временные, на 12 часов, сам секрет в браузер не попадает. Вместо coturn можно использовать готовый сервис: задайте `TURN_URLS`, `TURN_USERNAME` и `TURN_PASSWORD`.

Если оператор видит `НЕТ СОЕДИНЕНИЯ — НУЖЕН TURN`, значит, прямое соединение не получилось, а TURN не настроен или недоступен.

## Безопасность и исправление ошибок

- **ЭКСТРЕННАЯ ПАУЗА** всегда видна в шапке FIELD ADMIN. Она замораживает таймеры (при продолжении дедлайны сдвигаются на длительность паузы), блокирует сканирование, удары и потерю здоровья, а на телефонах экипажа показывает экран «оставайтесь на месте».
- Неверный статус исправляется в CREW → «исправить статус…». Ошибочное извлечение отменяется в SCRAP. Любая операция в ECONOMY отменяется корректирующей проводкой, а не правкой числа. Здоровье ведущий выставляет вручную: CREW → сотрудник → HP 0% / 50% / 100%.
- Баланс, здоровье, покупки и находки изменяются только на сервере. Повторный скан, повторная покупка, двойное нажатие «УДАР» и повторное опоздание не дают двойного эффекта.
- QR-метка лута содержит только случайный 128-битный токен, без цены и параметров. Токены видит только ведущий на странице печати.

При реальном происшествии безопасность важнее правил: ставьте игру на паузу.

## Структура

```
shared/types.ts      контракт снапшотов и событий
server/db.ts         схема SQLite и транзакции
server/game.ts       вся игровая логика (единственный источник истины)
server/snapshot.ts   снапшоты состояния с фильтрацией по ролям
server/routes.ts     HTTP API с проверкой ролей
server/realtime.ts   Socket.IO: рассылка состояния и событий
client/src/views     Operator, Admin (+ вкладки), Crew, Print
```

Данные лежат в `data/` (`game.db`, `secrets.json`, сертификат). Чтобы начать с чистого листа, удалите `data/game.db*`.
